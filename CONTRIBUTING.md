# Contributing to the FAIBOS Open Specification

We welcome contributions, RFC amendments, critiques, and implementation submissions from founders, operators, and software engineers.

## Ways to Collaborate

### 1. Propose an Amendment to the Specification (`SPEC.md`)
- If you have an improvement to the schemas, auth protocols, or security sandboxing rules, open an Issue titled `[RFC Amendment] <Topic>`.
- For specific wording or schema changes, fork the repository, make the changes to `SPEC.md`, and submit a Pull Request.
- Follow our core principle: **Simplicity first**. Reject speculative abstractions that add developer overhead without solving real business friction.

### 2. Submit a Project to the Market Scorecard
- Tracked implementations live in `src/data/implementations.ts`.
- If you build or know of an open-source agent harness, visual cockpit, or second-brain tool that matches or challenges FAIBOS criteria, open an Issue titled `[Scorecard] <Project Name>`.
- Provide:
  - Repository link.
  - Scores (0 to 5) across the six criteria: Zero-Install UI, 1-Click SOPs, BYOS Auth, Team Second Brain, Team RBAC, and Modular Plugins.
  - Known strengths and gaps relative to the FAIBOS standard.

### 3. Asynchronous Voice & Video Feedback
- If you prefer discussing ideas asynchronously directly with the primary author, leave a message on Samuel Michelot's sovereign video/audio channel at [contact.samuelmichelot.com](https://contact.samuelmichelot.com/?lang=en&source_site=faibos).

## Guidelines for Contributions
- **No AI Slope**: Write directly, concretely, and clearly. Avoid generic marketing hype or buzzword stuffing.
- **Punctuation rule**: Never use em dashes in documentation or code comments. Use commas, colons, parentheses, or periods.
